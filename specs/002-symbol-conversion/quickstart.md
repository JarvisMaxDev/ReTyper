# Quickstart: проверка преобразования символов

**Дата**: 2026-09-25 | **Контракт**: [contracts/conversion.md](./contracts/conversion.md)

## Предусловия

- macOS 12+; в системе есть раскладки Apple (устанавливаются вместе с macOS).
- Для ручной проверки у приложения ReTyper есть разрешения Accessibility и Input Monitoring.
- В «Active Keyboards» выбраны Polish и Russian – PC (настройка владельца), режим «Switch Only Last
  Word» выключен.

## 1. Автоматические проверки

```bash
swift test
```

Ожидается:
- Все тесты проходят, включая сверку эталонных раскладок на ANSI и ISO
  ([research.md, R9](./research.md#r9-тесты-и-ci)). Если эталонной раскладки нет, это ошибка
  теста, а не пропуск.
- Приёмочные примеры из [контракта](./contracts/conversion.md#внешний-контракт-что-видит-пользователь)
  проходят на системных раскладках.
- В коде нет ручных таблиц соответствий:
  `rg -n '"[a-z]": "[а-яёіїєґў]"' Sources/` ничего не находит.

## 2. Release-кандидат по конституции (принцип V)

Повторяет шаги задания `build` из `.github/workflows/build.yml`, кроме подписи сертификатом
«ReTyper Dev»: на машине владельца его нет (проверено 2026-09-25), поэтому локально подпись ad-hoc
(`-`). Подпись сертификатом проверяет CI.

```bash
swift test
MACOSX_DEPLOYMENT_TARGET=12.0 swift build -c release --arch arm64
MACOSX_DEPLOYMENT_TARGET=12.0 swift build -c release --arch x86_64
lipo -create .build/arm64-apple-macosx/release/ReTyper .build/x86_64-apple-macosx/release/ReTyper \
  -output ReTyper-universal
lipo -info ReTyper-universal                      # arm64 x86_64
bash scripts/test-package-release.sh
osascript -e 'quit app "ReTyper"'                 # один экземпляр приложения
mkdir -p ReTyper.app/Contents/MacOS
cp ReTyper-universal ReTyper.app/Contents/MacOS/ReTyper
codesign --force --sign - ReTyper.app
codesign --verify --deep --strict --verbose=2 ReTyper.app
open ReTyper.app
swift test -c release --filter KeyLayoutTests/testPairBuildTime
```

Ожидается:
- Тесты проходят; `lipo -info` показывает `arm64 x86_64`; тест упаковки и `codesign --verify`
  успешны.
- Свежий `ReTyper.app` запускается, в строке меню показывается текущая раскладка. Новая ad-hoc
  подпись может потребовать заново выдать Accessibility и Input Monitoring.
- `testPairBuildTime` выводит среднее время подготовки пары раскладок. Результат ≤ 5 мс (SC-006)
  записывается в `verification.md`.

После пуша в `main` (только по явному запросу; пуш запускает релиз) обязателен успешный CI
этой ревизии: `gh run list --commit <sha>`, затем `gh run watch <id>`. Локальная проверка его не
заменяет.

## 3a. Автоматический стенд

```bash
Tools/ReTyperStand/run.sh
```

Собственное приложение с одним полем и драйвер прогоняют сценарии 1–11 из таблиц ниже против
запущенного ReTyper. Драйвер нажимает двойной ⌥, только пока стенд активен, проверяет текст,
раскладку до и после, восстановление буфера (в сценарии 11 — RTF + текст), исход в журнале и
отсутствие в журнале тестового текста. Скриншоты своего окна и `report.json` сохраняются в
`Tools/ReTyperStand/out/<время>/`. Во время прогона (около минуты) ничего не печатать. Значок
раскладки у курсора на скриншотах может отставать от фактической раскладки — смотреть
`layoutBefore`/`layoutAfter` в отчёте. Стенд не заменяет проверку в живых приложениях.

## 3. Ручная проверка (выполняет владелец)

Приложения из SC-001: [TextEdit](https://support.apple.com/guide/textedit/welcome/mac),
[Safari](https://www.apple.com/safari/), [Telegram](https://telegram.org/),
[Visual Studio Code](https://code.visualstudio.com/) и
[OpenChamber](https://github.com/btriapitsyn/openchamber). Все установлены на машине владельца.
Перед каждым сценарием скопировать в буфер обмена известный текст, чтобы проверить его
восстановление. Сценарии 1–8 — это проверка без выделения (процесс п. 5).

| # | Действие | Ожидается |
|---|----------|-----------|
| 1 | Раскладка Polish, новая строка, набрать `^)`, двойной ⌥ | В поле `:)`, раскладка RU, буфер обмена прежний |
| 2 | Сразу ещё раз двойной ⌥ | `^)`, раскладка PL |
| 3 | Раскладка RU, набрать `:)` (Shift+6, Shift+0), двойной ⌥ | `^)`, раскладка PL |
| 4 | Раскладка PL, набрать `Ghbdtn^)`, двойной ⌥ | `Привет:)` |
| 5 | Раскладка PL, набрать `&`, двойной ⌥ | `?` |
| 6 | Раскладка PL, набрать `)))`, двойной ⌥ | Текст не меняется, раскладка переключается |
| 7 | Раскладка PL, клавиша `§` (слева от 1), двойной ⌥ | `ё` |
| 8 | Включить «Switch Only Last Word», набрать `ок ^)`, двойной ⌥ | `ок :)`, слово `ок` не тронуто; затем режим снова выключить |

Сценарии потока хоткея (процесс п. 5). Их достаточно выполнить в TextEdit и Safari:

| # | Действие | Ожидается |
|---|----------|-----------|
| 9 | Раскладка PL, набрать `abc ^) ^)`, мышью выделить `^) ^)`, двойной ⌥ | Выделение становится `:) :)`, `abc` не тронуто, раскладка RU |
| 10 | Пустое поле, курсор в начале, двойной ⌥ | Текст не появляется, переключается только раскладка, буфер прежний |
| 11 | В TextEdit (режим Rich Text) скопировать фрагмент с жирным шрифтом, чтобы в буфере были RTF и обычный текст. Затем выполнить сценарий 1 и вставить буфер в новый документ | Сценарий 1 проходит; вставляется исходный жирный фрагмент с форматированием, то есть все типы буфера восстановлены |

При ручной проверке замена символов не медленнее замены букв той же длины (SC-006).

Для визуального подтверждения (принцип V) — свежие скриншоты поля после сценария 1 и popover с
выбранными раскладками.

## 4. Журнал

Журнал: `~/Library/Caches/com.retyper.app/retyper.log`.

- После сценариев в нём есть строки `Conversion: source=… len=… target=…` с источником
  направления (`letters`, `layout-only symbols`, `current layout`, `undetermined`)
  ([R10](./research.md#r10-журнал)).
- Во **всём** журнале нет набранного текста (принцип I, процесс п. 8). Проверка:
  `grep -n -F -e '^)' -e ':)' -e 'Ghbdtn' -e 'Привет' -e 'abc' ~/Library/Caches/com.retyper.app/retyper.log`
  ничего не находит. Совпадения внутри служебных строк без пользовательского текста разбираются
  вручную и записываются в `verification.md`.
