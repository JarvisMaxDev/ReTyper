# Контракт: преобразование текста по нажатию хоткея

**Дата**: 2026-09-25 | **Модель**: [data-model.md](../data-model.md)

ReTyper не предоставляет API другим программам. Внешний контракт — наблюдаемое поведение хоткея.
Внутренний контракт — функция преобразования между `AppDelegate` и `ReplacementFlow`. Механизм
выделения, копирования и вставки задан фичей 001 и здесь не меняется.

## Внешний контракт: что видит пользователь

Условия: выбраны латинская раскладка L и кириллическая C, фрагмент F выбран по правилам фичи 001
(выделение, вся строка до курсора или последнее слово).

| Фрагмент F | Текущая раскладка | Результат в поле | Раскладка после |
|------------|-------------------|------------------|-----------------|
| Есть буквы, большинство латинские | любая | F по клавишам L→C | C |
| Есть буквы, большинство кириллические | любая | F по клавишам C→L | L |
| Буквы поровну | любая | без изменений | следующая (как сейчас) |
| Нет букв, есть символы только из L, нет только из C | любая | F по клавишам L→C | C |
| Нет букв, есть символы только из C, нет только из L | любая | F по клавишам C→L | L |
| Нет букв, есть символы только из L и только из C | любая | без изменений | следующая |
| Нет букв и символов только одной раскладки | L | F по клавишам L→C | C |
| то же | C | F по клавишам C→L | L |
| то же | не L и не C | без изменений | следующая |
| Результат равен F | — | без изменений | следующая |
| Нет L или нет C среди выбранных, либо у них нет данных клавиш | — | без изменений | следующая |

«По клавишам» — каждый символ заменяется тем, что даёт та же клавиша с тем же Shift в другой
раскладке на текущем типе клавиатуры. Символы без соответствия остаются прежними.

Примеры для Polish Pro + Russian – PC на ISO:

| F | Текущая | Результат |
|---|---------|-----------|
| `^)` | Polish Pro | `:)` |
| `:)` | Russian – PC | `^)` |
| `:)` | Polish Pro | `Ж)` |
| `&` | любая | `?` |
| `№` | любая | `#` |
| `Ghbdtn^)` | любая | `Привет:)` |
| `ok ^)` | любая | `щл :)` |
| `§` | любая | `ё` |
| `)))` | любая | без изменений |

## Внутренний контракт

```swift
enum TextConverter {
    /// Pure: no TIS calls, safe on any queue.
    static func convert(_ text: String,
                        layouts: [KeyLayout],          // selected order, already loaded
                        currentLayoutID: String) -> ConversionResult
}

extension KeyLayout {
    /// Main thread only. nil when the source is missing or has no key layout data.
    static func system(id: String, keyboardType: UInt32) -> KeyLayout?
}
```

Обязательства:
1. `convert` детерминирован: одинаковые аргументы дают одинаковый результат (принцип II).
2. `convert` не обращается к TIS, `NSPasteboard` и журналу с текстом. Он только возвращает
   `source`; строку журнала без текста пишет вызывающий код (FR-013).
3. `KeyLayout.system` и `LMGetKbdType()` вызываются в `AppDelegate.handleHotkey()` на главном
   потоке; в `replacementQueue` уходят готовые значения.
4. Сигнатура `ReplacementFlow.run(host:onlyLastWord:convert:)` не меняется. Замыкание
   `convert` возвращает `(converted, targetLayoutID)` из `ConversionResult`.
