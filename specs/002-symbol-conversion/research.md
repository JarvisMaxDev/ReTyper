# Research: Преобразование символов из системных раскладок

**Дата**: 2026-09-25 | **Спецификация**: [spec.md](./spec.md) | **План**: [plan.md](./plan.md)

Все замеры сделаны пробными программами на машине владельца: macOS 26.6.2, клавиатура ISO
(`LMGetKbdType() == 62`). Программы лежат вне репозитория, в `/tmp/retyper-probe/`, и в продукт не
входят.

## R1. Откуда брать символ клавиши

**Decision**: Данные клавиш читаются из `kTISPropertyUnicodeKeyLayoutData` (ресурс `uchr`)
через [`UCKeyTranslate`](https://developer.apple.com/documentation/coreservices/1390584-uckeytranslate)
из Carbon, который уже подключён в `Package.swift`. Для каждой клавиши основного блока
запрашиваются два состояния: без модификаторов и с Shift. Используется маска
`kUCKeyTranslateNoDeadKeysMask`: «мёртвая» клавиша сразу отдаёт свой символ и не ждёт следующую.
Константа `kUCKeyTranslateNoDeadKeysBit` — это номер бита (0), а не маска. С ней флаг не
передаётся, и «мёртвые» клавиши (в German `´` и `^` на ISO) не дают ничего. Найдено при
реализации 2026-09-25, см. [verification.md](./verification.md).

Набор клавиш зависит от типа клавиатуры (R2), потому что macOS описывает и клавиши, которых на
клавиатуре физически нет. Основа — виртуальные коды `0...50` без `10`, `36` (Return), `48` (Tab)
и `49` (Space). Для ISO добавляется `10` (клавиша `§`), для JIS — `93` и `94`.

Замер: на ANSI Russian – PC отдаёт `ё` и для кода `50` (`` ` ``), и для отсутствующего кода `10`.
Без исключения обратное `ё` дало бы `§`, которую на ANSI не напечатать.

Результат учитывается, только если это ровно один печатный символ, не пробел и не управляющий. Цифровая клавиатура и слой Option в область не входят (Assumptions спеки).

**Rationale**: Этот API возвращает именно то, что напечатает клавиша, с учётом раскладки и типа
клавиатуры. Он доступен на macOS 12+ и работает для раскладок, которые не включены в системе:
проверено на German, Russian и Byelorussian, не включённых у владельца.

**Alternatives considered**:
- Разбор файлов `.keylayout`. Отклонено: системные раскладки лежат внутри bundle в двоичном виде,
  файлов для них нет.
- Ручные таблицы. Запрещены принципом II конституции 6.0.0.
- Сравнение с символами из `NSEvent`. Отклонено: нужен реальный поток событий, в тестах его нет.

## R2. Тип клавиатуры

**Decision**: В приложении тип берётся из `LMGetKbdType()` в момент нажатия хоткея. В тестах он
передаётся явно: `40` (ANSI) и `41` (ISO). Тип определяется через `KBGetLayoutType`: `40/58/61`
дают `ANSI`, `41/59/62` — `ISO `, `42/60/63` — `JIS `.

**Rationale**: От типа зависит, что дают клавиши у левого края. Пример на ISO: в Russian – PC `ё`
печатается клавишей, которая в US даёт `§`; на ANSI — клавишей `` ` ``. Уведомления о смене
клавиатуры нет, поэтому тип читается при каждом нажатии хоткея, а не кешируется.

## R3. Когда строить соответствия и на каком потоке

**Decision**: Данные клавиш выбранных раскладок читаются при каждом нажатии хоткея в
`AppDelegate.handleHotkey()` на главном потоке, до перехода на `replacementQueue`. Там же сейчас
вызывается `relevantLayoutIDs()`. В фоновую очередь передаётся уже готовое неизменяемое значение.
Кеша нет.

**Rationale**:
- Все TIS-вызовы проекта уже выполняются на главном потоке; новый код следует этому.
- Замер: построение обоих направлений для Polish Pro ↔ Russian – PC после прогрева занимает
  1,3 мс (сборка без оптимизаций). Первый вызов в процессе — около 46 мс, это инициализация TSM.
  В приложении её заранее выполняет `relevantLayoutIDs()` при запуске, так что задержка первого
  хоткея не видна.
- Поиск раскладки по ID через `TISCreateInputSourceList(filter, true)` занимает 0,4 мс;
  с `includeAllInstalled: false` — 6,3 мс.
- Без кеша не нужна инвалидация при смене раскладок или клавиатуры (SC-006, FR-002).

**Alternatives considered**: кеш с перестройкой по `kTISNotifyEnabledKeyboardInputSourcesChanged`.
Отклонено: о смене типа клавиатуры система не уведомляет, а выигрыш — около 1 мс.

## R4. Правило коллизий

**Decision**: При построении соответствия «символ источника → символ цели» клавиши из набора R1 для
текущего типа клавиатуры перебираются сначала без Shift, затем с Shift, внутри — по возрастанию
кода клавиши. Побеждает первая клавиша, давшая символ.

**Rationale**: Правило простое и детерминированное (принцип II, FR-010). Оно сохраняет прежнее
поведение белорусского апострофа: `'` даёт `]` без Shift. Правило проверяется тестом.

## R5. Латинская или кириллическая раскладка

**Decision**: Раскладка считается кириллической, если среди её символов без Shift букв кириллицы
больше, чем латинских; латинской — наоборот. Иначе раскладка в преобразовании не участвует.

Латинская буква — ASCII `A–Z`, `a–z` и буквы диапазона U+00C0–U+024F (Latin-1 Supplement и
Latin Extended-A/B, без `×` и `÷`). Кириллица — U+0400–U+04FF, как сейчас.

**Rationale**: FR-002a. Ограничение латинских целей (`isSupportedLatinTarget`) снимается: немецкая
или Dvorak раскладка теперь описывается реальными данными. Расширенный латинский диапазон нужен,
чтобы текст с `ü`, `ł`, `ą` считался латинским при определении направления (FR-003). Это
изменение поведения внесено в [R8](#r8-расхождения-ручных-таблиц-с-macos-fr-011).

## R6. Направление для фрагмента без букв

**Decision**: Используются пара «первая латинская + первая кириллическая» из упорядоченного списка
выбранных раскладок (как сейчас) и правила по порядку:

1. Буквы есть — направление по большинству букв (FR-003), как в нынешнем `detectScript`, но с
   расширенным латинским диапазоном из R5.
2. Букв нет — берутся символы, которые в паре есть только у одной раскладки. Все такие символы
   фрагмента указывают на одну раскладку → направление от неё. Указывают на разные → не определено
   (FR-004).
3. Таких символов нет — текущая раскладка. Если она совпадает с латинской раскладкой пары, текст
   считается латинским; если с кириллической — кириллическим; иначе направление не определено
   (FR-005, FR-006).
4. Не определено или результат равен исходнику — текст не меняется. `ReplacementFlow` уже
   превращает это в `layoutOnly` (FR-007).

**Rationale**: Совпадает со спецификацией и Clarifications. Текущий ID раскладки получается на
главном потоке вместе с данными клавиш.

## R7. Где жили ручные таблицы и что остаётся

**Decision**: Файл `CharacterMap.swift` переименовывается в `LayoutCatalog.swift` (тип
`LayoutCatalog`). Из него удаляются все словари соответствий, `toEnglishMap`, `fromEnglishMap` и
`isSupportedLatinTarget`. Остаются списки ID, которые popover предлагает в «Active Keyboards», и
короткие названия для строки меню (`displayName`). Новый файл `KeyLayout.swift` содержит данные
клавиш одной раскладки и построение соответствий.

**Rationale**: Прежнее имя обещает таблицы символов, которых больше нет. Список предлагаемых
раскладок по спецификации не расширяется.

**Исправление в каталоге**: в macOS белорусская раскладка имеет ID
`com.apple.keylayout.Byelorussian`, а в коде записан `com.apple.keylayout.Belarusian`. Раскладки с
таким ID в системе нет, поэтому белорусская раскладка никогда не попадала в список и не
преобразовывалась. ID исправляется — иначе требования спеки для белорусской раскладки
невыполнимы. Это исправление ошибки, а не расширение списка.

Для справки о названиях в системе: `com.apple.keylayout.Ukrainian` — «Ukrainian – Legacy»,
`com.apple.keylayout.Ukrainian-PC` — «Ukrainian».

## R8. Расхождения ручных таблиц с macOS (FR-011)

Сравнение: латинская раскладка US против каждой кириллической. Столбец «Было» — результат прежней
таблицы, «Станет» — реальная клавиша. На ANSI и ISO результат одинаков, кроме строк с пометкой. Все строки с `§` / `±`
относятся только к ISO: на ANSI этой клавиши нет (R1).
Эти изменения поведения — ожидаемые (SC-004); остальные преобразования букв не меняются.

### Определение направления по буквам (все раскладки)

| Фрагмент | Было | Станет |
|----------|------|--------|
| Только буквы с диакритикой (`łąś`, `ü`) | Не считались буквами: направление не определялось, текст не менялся | Считаются латинскими, направление латиница → кириллица. Буквы, которых нет на клавишах основного блока без Option, остаются на месте. Поэтому `łąś` в Polish Pro фактически не меняется (только смена раскладки), а `ü` в немецкой раскладке (клавиша `[`) становится `х` |
| Смесь ASCII и кириллицы, где перевес дают буквы с диакритикой | Решал только ASCII | Буквы с диакритикой тоже учитываются в большинстве |

### Russian – PC (`RussianWin`, раскладка владельца)

| Ввод | Было | Станет | Примечание |
|------|------|--------|------------|
| `` ` `` / `~` | `ё` / `Ё` | ANSI: `ё` / `Ë` (латинская U+00CB); ISO: `]` / `[` | `Ë` — особенность раскладки Apple на ANSI; источник правды — система |
| `§` / `±` (только ISO) | без изменений | `ё` / `Ё` | На ISO `ё` на клавише `§` |
| `\|` | без изменений | `/` | |
| обратно `ё` / `Ё` | `` ` `` / `~` | ANSI: `` ` `` / без изменений; ISO: `§` / `±` | На ANSI `Ё` в этой раскладке не набирается |

### Russian (Apple)

| Ввод | Было | Станет |
|------|------|--------|
| `/` / `?` | `.` / `,` | `/` / `?` (одинаковы в обеих раскладках) |
| `` ` `` / `~` | `ё` / `Ё` | `]` / `[` |
| `\` / `\|` | без изменений | `ё` / `Ё` |
| `@ # $ % ^ & *` | без изменений | `" № % : , . ;` |
| `§` / `±` | без изменений | `>` / `<` |
| обратно `,` / `.` | `?` / `/` | `^` / `&` |

### Ukrainian – Legacy (`Ukrainian`)

| Ввод | Было | Станет |
|------|------|--------|
| `s` / `S` | `і` / `І` | `и` / `И` |
| `b` / `B` | `и` / `И` | `і` / `І` |
| `/` / `?` | `.` / `,` | `/` / `?` |
| `` ` `` / `~` | `ґ` / `Ґ` | `'` / `~` |
| `\` / `\|` | без изменений | `ґ` / `Ґ` |
| `@ # $ % ^ & *` | без изменений | `" № % : , . ;` |
| `§` / `±` | без изменений | `>` / `<` |

Здесь прежняя таблица ошибалась и в буквах: в «Ukrainian – Legacy» `і` стоит на месте `b`, а `и` —
на месте `s`.

### Ukrainian (`Ukrainian-PC`)

Ошибок нет, только добавления: `\` → `ʼ` (U+02BC), `|` → `₴`, `§` → `\`, `±` → `/`.

### Belarusian (`Byelorussian`)

Раньше не работала совсем из-за неверного ID (R7). С реальной раскладкой: `/`, `?` остаются собой;
`` ` `` → `“`, `~` → `„`; `\` → `ё`, `|` → `Ё`; `@ # $ % ^ & *` → `" № % : , . ;`; `§` → `’`,
`±` → `+`.

## R9. Тесты и CI

**Decision**:
- **Сверка раскладок.** Эталонные раскладки: US, ABC, Polish Pro, German (другое расположение
  букв), Russian, Russian – PC, Ukrainian, Ukrainian – Legacy, Byelorussian. Для каждой на типах
  `40` (ANSI) и `41` (ISO) ожидаемые символы записаны в тесте построчно, по рядам клавиатуры,
  без Shift и с Shift. Эти строки — проверочные данные (принцип II). Исходно они снимаются с
  системы и сверяются с таблицей R8 и примерами спецификации. Отсутствие раскладки — `XCTFail`,
  а не пропуск.
- **Логика направления, коллизий и обратимости** проверяется на синтетических `KeyLayout`, без TIS.
- **Приёмочные примеры спеки** проверяются на системных раскладках: `^)` → `:)`, `:)` → `^)`,
  `Ghbdtn^)` → `Привет:)`, ISO `§` → `ё`, `^&` → `,.` в Apple Russian, `н` → `z` в German.
- **CI.** `macos-14` в `.github/workflows/build.yml` уже запускает `swift test`. Раскладки Apple
  входят в систему, отдельная установка не нужна. Если на runner нет раскладки, тест упадёт, и это
  блокирует релиз, как требует конституция.

**Риск**: в другой версии macOS Apple может изменить раскладку. Тогда сверка упадёт, и ожидания
нужно будет осознанно обновить: именно так изменение не пройдёт незамеченным.

## R10. Журнал

**Decision**: Строка `Detected script` заменяется одной строкой с источником направления
(`letters`, `layout-only symbols`, `current layout`, `undetermined`), длиной фрагмента и ID целевой
раскладки. Текст и символы в журнал не пишутся (принцип I, FR-013).
