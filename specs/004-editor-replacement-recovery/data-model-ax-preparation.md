# Архив модели: отклонённая подготовка редактора

Дата: 2026-09-30. **Условный дизайн**: реализация после P0-01–P0-03 из [research.md](research.md).

## ApplicationIdentity

`pid`, `launchDate`. Ключ для подготовки. Повторное использование PID — другая identity.
При отсутствии launchDate подготовка не кешируется как успешная.

## PreparationAttempt

- `identity`: ApplicationIdentity.
- `token`: идентификатор текущей попытки, не переиспользуется.
- `state`: `requesting`, `waitingFollowUp`, `initialized`, `notNeeded`, `failed`.
- `startedAt`, `deadline`: монотонное время, общий бюджет ≤4 с.
- `requestCount`: 0…2.

Переходы: активация → requesting → waitingFollowUp → initialized. Ошибка/таймаут → failed;
атрибут отсутствует → notNeeded: этому приложению не нужен протокол подготовки.
Ошибка получения списка атрибутов → failed, а не notNeeded. Завершение процесса удаляет состояние и таймер.
Старая callback может менять состояние только при совпадении identity и token.

`initialized` означает только завершение протокола подготовки, **не разрешение замены**.
Повторные активации подготовленного процесса не вызывают запросы заново без причины.
Ошибка разрешает ограниченную новую попытку при следующей активации.

`notNeeded` не запрещает работу обычного нативного поля: оно проходит независимую проверку
SelectionObservation без AX-setter и задержки. Для протокольного приложения нужен `initialized`;
для остальных — `notNeeded`. Ни то ни другое само по себе не означает `eligibility=editor`.
`unsupported` относится только к конкретному полю в SelectionObservation, не к отсутствию
специального атрибута у приложения.

## FeedbackState

| Состояние | Сообщение при хоткее | Повторная попытка |
|---|---|---|
| requesting / waitingFollowUp | «Подготовка редактора…» | Новый хоткей после завершения; без автоматической замены |
| failed | «Не удалось подготовить редактор. Вернитесь в приложение и повторите» | Одна новая попытка при следующей активации; не на каждом хоткее |
| initialized / notNeeded + unverified | «Не удалось определить выделение. Текст не изменён» | Новое наблюдение на следующий хоткей; без повторного запуска подготовки только ради этого |
| eligibility=unsupported | «Это поле пока не поддерживается» | Новая проверка при смене поля |
| eligibility=editor | Обычный индикатор раскладки | Обычный хоткей |

Сообщение показывается только в ответ на хоткей, не перехватывает фокус и заменяется индикатором
раскладки через 3 с либо при смене контекста. Истечение времени сообщения не меняет готовность.
Терминальная панель/защищённое поле сохраняют обычное поведение layout-only без сообщения об ошибке.

## FocusContext

- `identity`: запуск приложения-получателя.
- `window`, `element`: непрозрачные ссылки на исходное окно и поле.
- `revision`: увеличивается при внешнем вводе, изменении окна/фокуса/активного приложения;
  обнаружение смены вкладки с повторным использованием элемента входит в P0-02.
- `secure`: запрещённый ввод, проверяется повторно перед эффектами.

Сравнение объектов — системная identity элементов, не их заголовок, текст или только PID.
Снимок и повторная проверка должны получать согласованный контекст: частично успешное чтение
нельзя дополнять данными из другого окна. Неудача инвалидирует операцию.

## SelectionObservation

- `context`: FocusContext.
- `eligibility`: `unverified`, `editor`, `terminal`, `secure`, `unsupported`.
- `range`: опциональные location/length в UTF-16.
- `origin`: существующее выделение пользователя или отсутствие выделения.

Свидетельство для перехода `unverified` → `editor` должно быть определено и проверено P0-01.
Его форма намеренно **не выдумана** в этом документе. Числа `(0,0)` сами по себе такого
свидетельства не дают. Роль `AXTextArea` и доступный текст также недостаточны.

Только для пригодного редактора length >0 разрешает копирование существующего выделения;
length ==0 допускает выделение клавишами с последующим подтверждением его ненулевой длины.
`unverified`, `terminal`, `secure`, `unsupported` не допускают команды редактирования.

## ReplacementAttempt

Существующие преобразователь и clipboard snapshot сохраняются. Попытка дополнительно содержит
исходный FocusContext, SelectionObservation, признак собственного выделения и исход операции.

Стадии: verify → select при необходимости → verify → copy → convert → verify → paste → restore.
При изменении контекста отменяются следующие команды; cleanup выделения разрешён только в
исходном поле. Восстановление буфера определяется его changeCount, не наличием фокуса.
Нет очереди отложенных хоткеев, автоматической вставки после подготовки и восстановления старой
операции после возврата пользователя в приложение.

## Хранение

Записи подготовки и контекст только в памяти, удаляются при завершении процесса/ReTyper.
Новых preferences и хранения потока нажатий нет. Журнал содержит состояние, длительность,
числовые ошибки и идентификатор приложения; не текст, заголовки документов и диапазоны ввода.
