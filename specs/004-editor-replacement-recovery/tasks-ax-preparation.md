## Dependencies & Execution Order

### Граф фаз

```text
T001 ─┐
      ├─ T003 → T004 → T005 [P0-01 PASS?]
T002 ─┘                       ├─ FAIL/BLOCKED → STOP, пересмотр плана
                              └─ PASS → T006 → T007 → T008 [все P0 PASS?]
                                                        ├─ нет → STOP
                                                        └─ да → US1 → US2 → US3 → финальный гейт
```

### Порядок внутри фаз

- T001 и подготовка инструмента T002 независимы. T003 требует оба результата. Живые проверки
  T003/T004/T006/T007 не выполняются параллельно: общий desktop и один исходный контекст.
- T006 зависит от PASS T005; T007 — от PASS T006; T008 требует PASS T004–T007.
- US1: T009 и T010 параллельно → T011 → T012 → T013 → T014 → T015.
- US2: T016 и T017 параллельно после US1 → T018 → T019 → T020.
- US3: T021 → T022 → T023 после US2.
- Завершение: после US3 T024 и T025 могут выполняться параллельно → T026 → T027 → T028 → T029 → T030.
- Одновременное редактирование `SystemReplacementHost.swift`, `AppDelegate.swift` или
  `ReplacementFlow.swift` разными задачами не разрешено.

### Зависимости историй

- US1 даёт обычную функцию, US2 проверяет и завершает её обязательную сохранность. US2 зависит
  от интерфейсов и интеграции US1, но её критерий проверяется отдельным сценарием частичного выделения.
- US3 зависит от интегрированного кандидата US1+US2, а её критерий — отдельная матрица старых сценариев.
- Минимальное функциональное исправление: **US1+US2**. US3 и полный финальный гейт обязательны
  перед использованием кандидата как готового исправления/выпуском; выпуск одной US1 запрещён.

## Implementation Strategy

1. **Сначала минимальный прототип, не новый production-механизм:** T001–T005.
2. P0-01 не проходит — прекращаем, сохраняем отрицательный результат и пересматриваем план.
3. P0-01 проходит — завершаем P0-02/03 и фиксируем точные интерфейсы T008.
4. Реализуем US1, затем US2. Каждый этап проверяет собственный пользовательский сценарий.
5. Проверяем US3, затем запускаем всю матрицу на свежем подписанном кандидате.
6. Коммит, пуш, release — отдельные явные действия владельца, не побочный эффект выполнения задач.
