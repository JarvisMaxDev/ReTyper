# Проверка восстановления редактора

Стенды вызывают настоящий хоткей запущенного ReTyper, а результат сверяют с собственным
сохранённым документом. Не направлять их в пользовательские документы. На время прогона не
печатать и не переключать окна; при потере получателя драйвер останавливается.

## Обычные сценарии

1. Открыть собственный `.txt` в отдельном окне [VS Code](https://github.com/microsoft/vscode).
   Для холодного запуска использовать отдельный `--user-data-dir`, accessibilitySupport=auto,
   не включать инспектор до первого сценария. Определить PID именно этого процесса.
2. Запустить свежий ReTyper, выбрать Polish + Russian – PC, двойной ⌥.
3. Выполнить из корня репозитория:

```bash
bash Tools/ReTyperStand/run-editor-recovery.sh PID /absolute/test/repro.txt /absolute/output 10
```

Девять сценариев: частичное выделение вперёд/назад, выделение при режиме слова, вся строка,
начало строки, пустое поле, последнее слово, символы, обратное направление. Проверяются текст,
раскладка и clipboard с RTF + текстом. Результат — `report.json`. Исходные раскладка, режим слова
и clipboard восстанавливаются в конце. Cold launch — свойство процесса, не каждого повтора.

Дополнительные флаги после числа повторов:
- `--reverse-first`: первое частичное выделение — обратное.
- `--performance`: 100 символов; время от последнего отпускания модификатора до фактически
  сохранённого результата (включает сохранение, поэтому это верхняя оценка времени замены).
  Ждать также наблюдаемую целевую раскладку: системное переключение асинхронно относительно журнала.
- `--scenario=partial-forward`: один выбранный сценарий.
- `--trace-clipboard`: изменения поколений/типов и классификация тестового содержимого;
  чужой текст не выводится.

Тот же драйвер можно направить в собственный plain-text документ другого нативного редактора,
если у него стандартные сочетания выбора/сохранения и заголовок окна содержит имя файла.
Неподдержанный формат окна не обходится отключением проверки получателя.

## Отмена и запрещённые поля

```bash
swiftc -O Tools/ReTyperStand/EditorRecoveryGuards.swift -o Tools/ReTyperStand/build/editor-recovery-guards
Tools/ReTyperStand/build/editor-recovery-guards CODE_PID /absolute/test/repro.txt /absolute/output TEXTEDIT_PID /absolute/native-probe.txt
```

Нужны два собственных окна: обычный редактор и plain-text документ TextEdit. Проверяются поиск,
терминальная панель, ввод/смена поля/приложения/уход-возврат во время копирования, чужое изменение
clipboard и системный защищённый ввод. Защищённый режим снимается самим драйвером.

Для смены окна внутри одного процесса открыть второе тестовое окно VS Code с файлом
`window-target.txt` рядом с `repro.txt`, содержащим ровно `untouched-target` и один перенос строки.
Повторить команду с `--window-only`: проверяется смена окна и пользовательское копирование в нём.
Целевой документ сохраняется и сверяется; он не должен получить чужую вставку.

Отчёт содержит фактически выполненные проверки. Отказ самого приложения принимать Paste
и все возможные гонки доставки событий ОС этим стендом не доказываются. Такие ограничения
не превращать в PASS. Зафиксированные сбои и прерванные прогоны сохранять рядом с успешными.
